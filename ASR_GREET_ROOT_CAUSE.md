# Expected greet flow (happy path)
- **WS open → session init:** Server establishes the ChatV2Adapter context and awaits greet handling.
- **Greet TTS start:** First TTS frame for greet calls `_handle_tts_start`, marking `ctx.session.tts_active = True` and ensuring greet turn bookkeeping. 【F:app/ws/adapter.py†L1090-L1110】
- **Greet TTS end:** When the greet utterance finishes, `_handle_tts_end` marks `greet_completed = True` when the frame signals greet (via `meta.is_greet`/`meta.greet`/`reason="greet"` or `greet.*` frame types). It emits `greet.completed`/`greet.complete` and then immediately calls `_ensure_asr_ready` to arm ASR. 【F:app/ws/adapter.py†L1219-L1273】【F:app/ws/adapter.py†L7715-L7773】
- **ASR ready bundle:** `_ensure_asr_ready` (only after `greet_completed`) schedules `_open_asr`, waits for it, and sends the `asr.ready + input.start + start_listening` bundle. This sets `asr_ready_bundle_sent_ms`, arms client capture, and records mic arm time. 【F:app/ws/adapter.py†L1035-L1086】【F:app/ws/adapter.py†L7609-L7655】
- **ASR open → ingestion:** When audio frames arrive, `handle_audio` increments `ing_frames/bytes/chunks` and keeps the ingress tick timer running for telemetry. ASR engine streams audio for decoding. 【F:app/ws/adapter.py†L3850-L3893】【F:app/ws/adapter.py†L6280-L6327】
- **Ingress ticks:** Every ~2s `_emit_ingress_tick` logs `audio.ingress.tick` with frame/byte/chunk counts and resets counters. Non-zero audio produces non-zero counts. 【F:app/ws/adapter.py†L6280-L6334】

# Failure mode: greet_not_completed / asr_closed_pre_open with 0 bytes
- **`reason="greet_not_completed"`:** `_ensure_asr_ready` exits early and emits `asr.skip_pre_greet` when `ctx.greet_completed` is False. Any client `asr.open` before greet also logs `asr.open_ignored_pre_greet` with the same reason. 【F:app/ws/adapter.py†L1045-L1052】【F:app/ws/adapter.py†L3018-L3027】
- **`where="asr_closed_pre_open"`:** On an ASR `closed` event where no bytes were sent, no open timestamp was recorded, no ready bundle was sent, and `ctx.asr_open` is False, the adapter treats it as a pre-open close and re-invokes `_ensure_asr_ready` with label `asr_closed_pre_open`. 【F:app/ws/adapter.py†L4815-L4847】
- **`audio.ingress.tick` zero counters:** The tick event reports `frames=0, bytes=0, chunks=0` when `ctx.ing_frames/ing_bytes/ing_chunks` are zero—meaning no PCM chunks passed through `handle_audio` since the previous tick. Counters only increment inside `handle_audio` when audio data bytes are ingested. 【F:app/ws/adapter.py†L6302-L6327】【F:app/ws/adapter.py†L3850-L3893】

# Likely root cause in current setup
- **Greet never marked complete:** Greet TTS audibly plays, but the server never sets `ctx.greet_completed`, likely because the TTS frames lack the greet markers `_handle_tts_end` checks (`type` in `{greet.end,greet.complete}` or `meta.is_greet/meta.greet/reason="greet"` or matching `greet_utt_id`). Without that flag, `_ensure_asr_ready` bails with `greet_not_completed`, preventing ASR readiness and leaving `asr_ready_bundle_sent_ms` unset. 【F:app/ws/adapter.py†L1219-L1273】【F:app/ws/adapter.py†L7715-L7773】【F:app/ws/adapter.py†L1035-L1052】
- **ASR never actually opened:** Because ASR readiness is skipped, any downstream ASR closed event matches the pre-open condition (`asr_bytes_sent == 0` and `asr_opened_ms/asr_ready_bundle_sent_ms` unset), producing `asr_closed_pre_open`. With no `start_listening` sent, the client likely withholds PCM, so `handle_audio` never runs and ingress tick counters remain zero, yielding `audio.ingress.tick` with 0 frames/bytes/chunks. 【F:app/ws/adapter.py†L4815-L4847】【F:app/ws/adapter.py†L7609-L7655】【F:app/ws/adapter.py†L6280-L6327】
